# معماری Customer Journey Kernel در v4.4.0

## هدف نسخه

نسخه 4.4.0 نخستین هسته عملیاتی «هیچ مشتری گم نشود» است. این نسخه CRM دیگری کنار دیدار نمی‌سازد؛ داده‌های تماس، هویت مرکزی، حسابداری و تعامل فروشنده را با کلید اصلی `IdentityId` به یک صف اقدام قابل‌کنترل وصل می‌کند.

قاعده مرکزی سیستم:

> هر سرنخ یا فرصت فعال باید مالک، اقدام بعدی، موعد اقدام و زمان SLA داشته باشد.

اگر کار از SLA عبور کند، در مرکز کنترل مدیریت نمایش داده می‌شود.

## مرز ایمنی با سیستم فعلی

- مسیرهای `/agent` و `/seller-v2` و ساختار فعلی ثبت تماس حفظ شده‌اند.
- قابلیت جدید با `JourneyKernel:Enabled=false` خاموش است.
- migration تنها وقتی قابلیت برای پایلوت روشن شود اجرا می‌شود.
- پایلوت می‌تواند فقط برای یک یا چند `SellerKey` فعال شود.
- اتصال خودکار نتیجه‌های Seller v2 یک سوییچ جدا با نام `AutoCaptureSellerInteractions` دارد و در شروع خاموش است.
- خطای capture جدید هیچ‌وقت پاسخ موفق Seller v2 را خراب نمی‌کند؛ فقط در log ثبت می‌شود.

## مدل داده افزایشی

| جدول | مسئولیت |
|---|---|
| `JourneyLeads` | سرنخ با مالک، وضعیت، اقدام بعدی و SLA |
| `JourneyOpportunities` | فرصت فروش و مرحله جاری Pipeline |
| `JourneyOpportunityProducts` | محصول و مقدار فرصت |
| `JourneyOpportunityStageHistory` | تاریخچه غیرقابل‌ابهام تغییر مرحله |
| `JourneyWorkItems` | صف کار فروشنده و اقدام بعدی اجباری |
| `JourneyEvents` | رویدادهای سفر مشتری با `IdentityId` |
| `JourneyOutbox` | تحویل قابل‌اعتماد رویدادها به ماژول‌های آینده |
| `JourneySlaPolicies` | سیاست زمان پاسخ و پیگیری |
| `JourneyLegacyLinks` | اتصال بدون دستکاری داده قدیمی |

هیچ جدول مشتری یا تلفن تازه‌ای ساخته نشده است. مرجع هویت همان `CustomerIdentities.IdentityId` و تلفن‌ها همان `CustomerIdentityPhones` هستند.

## جریان عملیاتی پایلوت

1. فروشنده با حساب فعلی وارد `/seller-v3` می‌شود.
2. مشتری موجود را با نام یا تلفن پیدا می‌کند.
3. سرنخ را همراه اقدام بعدی و زمان آن ثبت می‌کند.
4. سرنخ پس از تأیید نیاز به فرصت فروش تبدیل می‌شود.
5. هر تغییر مرحله، اقدام بعدی تازه می‌سازد.
6. تکمیل یک کار، یا مشتری را می‌بندد یا کار کنترلی بعدی می‌سازد؛ بنابراین موجودیت فعال بدون کار رها نمی‌شود.
7. مدیر موارد عبورکرده از SLA را در `/journey-control` می‌بیند.

## مرحله‌بندی فرصت

`DISCOVERY → NEEDS_CONFIRMED → PRICE_GIVEN → QUOTE_SENT → DECISION → NEGOTIATION → WON/LOST`

مرحله `ON_HOLD` برای توقف موقت وجود دارد، اما همچنان اقدام و موعد بعدی لازم دارد.

## APIهای جدید

- `GET /api/seller-v3/status`
- `GET /api/seller-v3/workspace`
- `POST /api/seller-v3/leads`
- `POST /api/seller-v3/leads/{id}/qualify`
- `POST /api/seller-v3/opportunities/{id}/stage`
- `POST /api/seller-v3/work-items/{id}/complete`
- `GET /api/journey-control/exceptions` (فقط مدیریت)

تمام mutationها `IdempotencyKey` می‌خواهند و مالک از session معتبر فروشنده گرفته می‌شود، نه از ورودی مرورگر.

## برنامه استقرار بدون ریسک

### مرحله صفر — نصب خاموش

`RUN-v4.4.0.cmd` اجرا می‌شود. فایل‌ها نصب می‌شوند اما Seller v3 خاموش می‌ماند. Seller v2 مسیر تولید است.

### مرحله یک — پایلوت دستی یک فروشنده

با `CONFIGURE-JOURNEY-PILOT-v4.4.0.ps1` فقط یک `SellerKey` فعال می‌شود. `AutoCaptureSellerInteractions` خاموش می‌ماند و داده‌ها از UI جدید ثبت می‌شوند.

معیار عبور:

- ثبت و تکمیل حداقل ۳۰ کار واقعی؛
- صفر خطای ثبت Seller v2؛
- صفر سرنخ فعال بدون Work Item؛
- تأیید فروشنده و مدیر روی صف کار و SLA.

### مرحله دو — Capture خودکار پایلوت

پس از تأیید مرحله یک، capture تعامل Seller v2 فقط برای همان کاربر روشن می‌شود. خطاهای capture از مسیر فعلی ایزوله‌اند.

### مرحله سه — توسعه تدریجی

پس از مشاهده یک هفته داده واقعی، کاربران دیگر اضافه می‌شوند. جایگزینی عمومی Seller v2 در این نسخه انجام نمی‌شود.

## rollback

- خطای نصب باعث rollback خودکار و Health Check نسخه قبلی می‌شود.
- `ROLLBACK-v4.4.0.cmd` آخرین backup همین نسخه را برمی‌گرداند.
- جداول جدید حذف نمی‌شوند؛ چون افزایشی و برای نسخه قبلی نامرئی‌اند.
- فایل‌های مختص v4.4 به قرنطینه داخل backup منتقل می‌شوند و قابل بازیابی‌اند.

## خارج از دامنه این نسخه

- ارسال خودکار پیامک و صفحه عمومی سفارش؛
- امتیازدهی هوش مکالمات به فرصت فروش؛
- پیش‌فاکتور، تحویل و رضایت به‌صورت first-class؛
- تغییر ساختار Canonical Phone؛
- جایگزینی دیدار یا نرم‌افزار حسابداری.

این موارد پس از تثبیت Journey Kernel روی داده واقعی وارد نسخه‌های بعد می‌شوند.
